# anal 스킬 설계

작성일: 2026-10-03

## 목적

DART 정기보고서로 한국 상장사를 내 기준(연속 성장, 영업이익률 유지)으로 판정하고, 판정 뒤 질의로 내용을 확인한다. 질의의 근거는 DART 정기보고서, 로컬 파일, 구글 드라이브 자료 폴더뿐이며, 없으면 없다고 답한다.

결과물은 `CLAUDE.md`, `원칙.md`, `SKILL.md`와 이를 받치는 스크립트다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 기존 `dart-analyst`와의 관계 | `testproject`에 새로 만든다. 기존 스크립트를 복사해 출발점으로 쓰고, 기준과 절차는 새로 정한다 (서로 독립) |
| 스킬 이름 | `anal` |
| 기준 | 2개 (아래). 기존 세 기준과 FnGuide는 쓰지 않는다 |
| 근거 범위 | DART 정기보고서(분기·반기·사업), `data/` 로컬 파일, 구글 드라이브 자료 폴더 |
| 데이터 위치 | `testproject/data/` (상위 `stockanalyst/data/`와 공유하지 않음) |

## 흐름

### 분석 모드 ("○○ 분석해 줘")

1. `dart_fetch.py <회사>`: 다음 두 보고서를 받는다.
   - 최근 사업보고서 1건
   - 그 사업보고서 이후에 나온 올해 최신 정기보고서(1분기·반기·3분기 중 가장 최근) 1건. 없으면 받지 않는다.
   - 두 보고서의 재무 원자료(`재무_*.json`)와 원문(`원문/*.txt`)을 저장하고, 판정 입력인 `annual.json`을 만든다.
2. `analyze.py <회사>`: 두 기준을 판정해 `분석/<날짜>.md`와 `.json`을 저장한다.
3. `drive_search.py <회사명> [별칭...]`: 드라이브에서 종목 자료를 찾아 요약한다.
4. 판정 표, 종합 결과, 보고서 링크를 보여 준다. 투자 의견은 덧붙이지 않는다.

### 질의 모드 ("○○의 △△는?")

- 해당 종목 폴더가 있으면 `data/` 파일과 드라이브 자료에서 찾는다. 없으면 수집할지 묻는다.
- 답의 문장마다 출처를 붙인다(형식은 원칙.md).
- 찾지 못하면 정확히 "DART 정기보고서와 로컬 파일에서 찾을 수 없습니다."라고 답한다.

## annual.json

`analyze.py`가 읽는 유일한 입력이다. 숫자마다 출처(보고서, 계정, 접수번호)를 함께 저장한다.

- **연간**: 사업보고서 손익계산서의 `thstrm_amount`(당기), `frmtrm_amount`(전기), `bfefrmtrm_amount`(전전기)에서 매출액과 영업이익. 3개 연도.
- **올해 누적**: 올해 최신 보고서의 누적 금액과 전년 같은 기간 누적 금액.
  - 반기·3분기보고서: `thstrm_add_amount`, `frmtrm_add_amount`
  - 누적 필드가 비어 있으면(1분기보고서 등) `thstrm_amount`, `frmtrm_q_amount` (1분기는 3개월 = 누적)
- 계정 식별은 기존 `dart_fetch.py`의 `pick()` 방식(계정 ID 우선, 계정명 보조)을 따른다.
- 재무제표는 연결 우선, 연결이 없을 때만 별도. 어느 쪽인지 기록한다.

## 판정 규칙

### 기준 1. 매출·영업이익 연속 성장

| 조건 | 통과 조건 |
|---|---|
| 1-a 연간 | 최근 3개 연도에서 매출과 영업이익이 각각 매년 증가 (전전기 < 전기 < 당기) |
| 1-b 올해 | 올해 누적 매출과 누적 영업이익이 각각 전년 같은 기간보다 큼 |

- 1-a와 1-b를 모두 만족해야 통과.
- 적자 감소도 증가로 본다 (예: −100 → −50). 원 단위 숫자 크기로 비교한다.
- 같은 값은 증가가 아니다(탈락).
- 올해 정기보고서가 아직 없으면 1-b는 `해당 없음`이며, 기준 1은 1-a만으로 판정하고 보고서에 그 사실을 적는다.

### 기준 2. 영업이익률 유지

| 조건 | 통과 조건 |
|---|---|
| 연간 | 최근 3개 연도에서 영업이익률이 매년 같거나 오름 |

- 영업이익률 = 영업이익 ÷ 매출 × 100, 소수점 둘째 자리에서 반올림한 값으로 비교한다.
- 올해 누적은 보지 않는다.

### 공통

- 판정은 `통과`, `탈락`, `판정 불가` 중 하나. 두 기준을 모두 끝까지 계산한다.
- 종합 결과는 "2개 기준 중 N개 통과".
- 12월 결산 법인만 지원한다. 그 외는 분석하지 않고 알린다.

### 판정 불가

| 상황 | 결과 |
|---|---|
| 사업보고서가 없거나 3개 연도 중 숫자가 빠짐 (상장 3년 미만 등) | 1-a 판정 불가, 기준 2 판정 불가 |
| 3개 연도 중 매출이 0 이하인 해가 있음 | 기준 2 판정 불가 |
| 올해 보고서는 있으나 누적 숫자가 빠짐 | 1-b 판정 불가 |

기준 1 종합: 1-a·1-b 중 하나라도 `탈락`이면 `탈락`(이미 확정), 아니고 하나라도 `판정 불가`면 `판정 불가`, 나머지는 `통과`. 1-b가 `해당 없음`이면 1-a 결과를 따른다.

## 분석 보고서 (`분석/<날짜>.md`)

- 회사명, 종목코드, 기준 재무제표(연결/별도), 사용 보고서와 접수번호
- 기준별 판정과 조건별 수치 표 (연도별 매출·영업이익·영업이익률, 올해 누적 대 전년 동기)
- 숫자마다 출처
- 종합 결과
- `.json`에는 같은 내용을 기계가 읽을 수 있게 저장

## 원칙.md 내용

- 근거 범위: DART 정기보고서, `data/` 로컬 파일, 구글 드라이브 폴더. 자료 성격 구분(DART 확정 공시 / IR 회사 주장 / 리포트 제3자 의견), 숫자가 다르면 DART 우선. 웹 검색·뉴스·사전 지식 금지. 근거에 있는 숫자로 계산한 값은 출처와 계산식을 함께 보이면 답할 수 있다.
- 분석 기준: 위 판정 규칙.
- 출처 표시 형식: 기존 원칙.md 3절에서 FnGuide 줄을 뺀 형식.

## CLAUDE.md 내용

- 프로젝트 한 줄 설명, 반드시 지킬 것(원칙.md·SKILL.md 따르기, 근거 범위, 문장마다 출처, 계산과 판정은 스크립트), 환경(`py`, `pypdf`, `G:` 드라이브, `.env` 키 값 비노출), 폴더 구조, 기준 변경 시 `원칙.md`와 `analyze.py`를 함께 고칠 것.

## 오류 처리

- 회사명이 여러 회사에 해당하면 종료 코드 2와 후보 목록. 스킬은 짐작하지 않고 사용자에게 묻는다.
- 12월 결산이 아니면 오류로 멈춘다.
- DART API 오류(키 없음, 한도 초과, 응답 상태 ≠ 000)는 메시지를 그대로 알린다.
- 드라이브 폴더가 없으면 알리고 나머지 단계는 계속한다.

## 테스트

- `test_analyze.py`: 판정 함수에 가짜 숫자를 넣어 확인한다.
  - 매년 증가 → 통과, 같은 값 → 탈락, 적자 감소 → 증가로 인정
  - 1-b 해당 없음 → 1-a만으로 판정
  - 연도 누락 → 판정 불가, 매출 0 → 기준 2 판정 불가
  - 영업이익률 같은 값 → 통과, 하락 → 탈락
- 실제 종목 1개로 수집 → 판정 → 질의까지 끝까지 실행한다.
